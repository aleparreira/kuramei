# Contributing to Kuramei

> Conduct systems, not just build them.

If you're here, you're already a Maestro. Welcome.

---

## How to Contribute

### First time?

1. Fork the repo
2. Pick a [`good-first-issue`](https://github.com/aleparreira/kuramei/labels/good-first-issue)
3. Submit a PR following the template
4. We'll review within a week

### Have an idea?

Open a [Discussion](https://github.com/aleparreira/kuramei/discussions) first. Let's talk before you code.

### Found a bug?

Open an [Issue](https://github.com/aleparreira/kuramei/issues) with steps to reproduce.

---

## Pull Request Guidelines

### Keep it focused
- One thing per PR
- Small PRs get reviewed faster

### Make it clear
- Describe what and why
- Link related issues

### Make it pass
- CI must be green
- Tests if applicable

### PR Size Guide

| Type | Description |
|------|-------------|
| **Typo/Docs** | Text only, no logic |
| **Small** | ≤ 50 lines, 1-2 files |
| **Medium** | 50-200 lines, ≤ 5 files |
| **Large** | > 200 lines or new feature |

Large PRs may be asked to split.

---

## Code of Conduct

Be direct. Be respectful. Focus on the work.

---

## Becoming a Maintainer

There's no application. Keep contributing well.

Maintainers are Contributors who:
- Contribute consistently with quality
- Understand the project direction
- Communicate clearly

When the time is right, you'll be invited.
